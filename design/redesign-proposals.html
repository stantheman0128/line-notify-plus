Notify+ · Design Exploration

三個彼此互斥的 App 設計方向

現況：Notify+ 是一個功能已經完成的 NotificationListenerService 工具，但它的 UI 是一張「設定清單」—— 首頁把 App 最有價值的東西（它其實握有你所有 LINE 訊息的本機副本、以及重組通知的能力）全都藏在開關後面。 下面三個方向不是三種配色，而是三種不同的產品命題：每一個都會改變首頁、資訊架構、以及你之後該做什麼功能。

Kotlin · Jetpack Compose minSdk 26 / targetSdk 35 零網路權限 · 純本機 v1.3.1 / vc17 待送審 已解除 Impersonation 退件

為什麼要重新設計 — 現況的四個結構性問題

01 · 首頁
首頁是設定頁，不是產品

使用者開 App 只看到「服務運行中」+ 兩個開關。裝完之後沒有任何回訪理由，App 的價值 100% 發生在通知列，使用者永遠不會回來。

02 · 信任
最敏感的權限，最少的透明度

通知存取權能讀到全部訊息。目前 UI 完全沒有告訴使用者「我讀了什麼、做了什麼、沒有傳出去」——而這剛好是這類 App 最大的下載阻力。

03 · 規模
聊天室管理無法擴張

幾百個聊天室 × 一個開關的平面清單。沒有批次操作、沒有優先級、沒有「只擋 @all」這種真實需求（ROADMAP 已列但無處可放）。

04 · 品牌
視覺仍依附 LINE 綠

vc12 曾因 Impersonation 退件。雖已放行，主色仍是 #06C755＋動態取色，等於沒有自己的識別，也無法延伸到官網／截圖／宣傳。

Notify+ ↗ A · Control Room B · Second Inbox C · Focus Engine 對照與建議
DIRECTION A

Control Room 把看不見的背景服務，變成看得見的儀表板

命題：這個 App 的產品其實是「信任」。它要求的是 Android 上最敏感的權限之一， 所以首頁不該是開關，而該是一個誠實的控制台：現在在聽什麼、今天處理了幾則、合併了幾次雙 callback、 哪些能力做不到（例如「在 LINE 內直接讀」收不到已讀信號）。 這個方向幾乎不需要新的核心邏輯——你的 listener 已經產生了這些事件，只是從來沒顯示出來。

DIRECTION B

Second Inbox 你已經握有全部訊息了 — 為什麼不做成收件匣？

命題：從工具升級成每日必開的 App。你的 ChatMessage 已經存著每個聊天室的訊息串、頭貼、 時間、以及可用的 PendingIntent 與 RemoteInput。等於你已經有一個完整的「LINE 通知收件匣」， 卻只把它渲染到系統通知列就丟掉。這個方向把它變成 App 內的 triage 介面：分堆、VIP、延後、 直接回覆、以及 ROADMAP 上的跨聊天室搜尋（這是 LINE 自己都難用的功能）。

DIRECTION C

Focus Engine 使用者要的不是「整理通知」，是「安靜」

命題：從整理器變成過濾器。真正的痛點不是通知排版醜，而是 LINE 群組太吵、 又不敢完全關掉怕漏掉重要訊息。這正是 ROADMAP 上那幾條做不完的需求 （只擋 @all、保留 @我、個別靜音、回覆後清除）真正的歸屬地——它們不是散落的開關， 而是同一個東西：規則引擎 + 情境模式。這個方向能做出 LINE 官方永遠不會做的事。

為什麼會贏

  • 直接命中真實痛點：群組吵但不敢關
  • ROADMAP 那幾條孤立需求終於有了統一的家
  • LINE 官方不可能做「過濾自家通知」→ 天然護城河
  • 規則數／命中數天然形成 free vs pro 的切分線

  • 規則資料模型（條件 → 動作）＋評估順序
  • 情境模式與時間排程（含 DND 互動）
  • 摘要投遞（累積 + 定時 flush）
  • @all vs @我 的可靠偵測 — 需先在多 OEM 蒐集真實 extras，不可用可見文字猜

  • 🔴 漏一則重要訊息 = 直接一星，必須全程 fail-open
  • @all 偵測目前尚無跨 OEM 實證資料（ROADMAP 已標未完成）
  • 規則 UI 容易做成工程師專用 → 必須靠預覽與範本救
  • 與系統 DND／專注模式可能語意衝突，需明確說明優先權

可否疊加 A 是 B、C 的地基（兩者都需要「被擋下／被處理」的可追溯清單）。A → C → B 是風險最低的順序：先建立信任，再賣安靜，最後才碰訊息儲存。

如果目標是「盡快上架」

  • 選 A。不動核心邏輯、不碰 Data safety 答案，只把已有事件可視化
  • 順手解決品牌問題：Indigo 主色徹底脫離 LINE 綠，截圖與 feature graphic 一次到位

如果目標是「產品差異化」

  • 選 C。這是唯一 LINE 官方做不到、且能收費的方向
  • 但必須先補完 @all／@我 的跨 OEM extras 實證，否則規則不可靠

如果目標是「做成真正的 App」

  • 選 B，但要有意識地接受：隱私敘事從此改變、工期翻倍
  • 建議先上 A 或 C，用真實使用者驗證需求後再投入
