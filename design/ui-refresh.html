Notify+ · Option 0 — UI Refresh

只改介面，不動任何功能

這一版把前面三個方向全部放掉，回到一個假設：Notify+ 現有的功能就是對的，問題出在它們被排版的方式。 實際讀過 strings.xml 與 MainActivity.kt 之後，這個假設更站得住腳—— 像 OEM 背景常駐排查、隱私說明、批次選取、手動更正分類、權限兩步驟引導，其實都已經做完了， 只是被壓在 FAQ 與摺疊區裡，使用者看不到。

這一版明確不做
  • 不新增任何設定、頁面或能力
  • 不加網路權限、不存訊息、不做帳號
  • 不動 listener、classifier、通知組裝邏輯
  • 不改 Data safety 答案（維持 No data collected）
這一版只做
  • 資訊層級：誰該大、誰該小、誰從屬於誰
  • 把既有但藏起來的東西（通知風格）提到檯面
  • 綠色留著，但只用在對的元件上
  • 元件與排版重做、補齊深色模式

診斷

六個純視覺／層級問題（都不需要動功能）

01
所有東西都是同一種份量

Arrangement.spacedBy(16.dp) 把狀態卡、設定卡、三顆按鈕、進階卡排成一串等寬等重的方塊。畫面上沒有任何東西告訴你「先看這個」。

做法：建立三層階層——主控制、次要設定、入口連結，各自用不同的容器與字級。
02
狀態卡在「沒事」時最吵

ServiceStatusCard 永遠佔一整塊 primaryContainer。但服務正常時它不需要說話；真正需要它放大的是壞掉的時候，那時它卻跟平常一樣大。

做法：正常時縮成一行狀態條；異常時才膨脹成含行動步驟的警示卡。
03
核心決策被摺在「進階功能」裡

對話串 vs Apple 分組是使用者唯一真正要選的東西，也是這個 App 的賣點，卻收在 AdvancedSettingsCard 的摺疊區，新使用者永遠不會展開。

做法：提到首頁第二順位，做成兩張帶縮圖的選擇卡，取代 radio 清單。
04
從屬關係沒有被畫出來

「取代原始通知」在邏輯上依賴主開關，後果也更大（會蓋掉 LINE 自己的通知），但視覺上跟主開關長得一模一樣、並排在同一張卡。

做法：主開關獨立放大，「取代原始通知」縮排成子項，主開關關閉時淡化。
05
視覺重量完全倒置

整頁最搶眼的是綠色實心的「加入 Notify+ 官方帳號」，但它是最不重要的動作。真正的主開關反而是灰卡裡的一列。

做法：三個入口（聊天室／FAQ／官方帳號）降級成一組列表，把實心按鈕留給主要動作。
06
綠色沒問題，但它其實沒有出現

dynamicColor = true 讓 Android 12+ 直接改用使用者桌布取色。也就是說大多數使用者看到的根本不是 LINE 綠，而是隨機的紫、橘、藍。你的品牌色形同虛設，截圖也永遠對不上實機。

做法：關掉動態取色，讓綠色真的是綠色；並把綠色從「最不重要的按鈕」移到主控制與選取態。

首頁：把層級畫出來

  • 狀態縮成一行。正常運作時它只需要一顆綠點加一行字，省下的整塊空間留給真正的控制項。
  • 主開關獨立成一張白卡，是全頁唯一有陰影、字最大的元件。「取代原始通知」縮排在它底下、開關變小，從屬關係一眼看得出來，資訊圖示也保留原本的 dialog 說明。
  • 通知風格從摺疊區拉出來，變成兩張帶通知縮圖的卡。這是原本就有的設定，只是第一次真的被看見——縮圖用的是 NotificationStyleVisualGuide 已經在畫的那組示意。
  • 「通知清除時機」用回 strings 裡本來就有的 clear_timing_title 當分組標題，兩個開關終於有了歸屬，不再是一串平鋪的列。
  • 四個入口收成一組列表。官方帳號從全頁最搶眼的綠色實心按鈕，降級成一列——它本來就不是主要動作。
  • 底部一行常駐聲明。這句話 chat_info_privacy_body 裡已經有了，只是藏在聊天室說明的 dialog 深處。

未授權：狀態卡與引導卡不該同時存在

  • 現況會同時出現兩張卡在講同一件事：紅色的「✗ 服務未啟用」和底下的「完成 2 個權限設定」。第一張沒有帶任何資訊或動作，純粹是重複。
  • 合併成一張。標題改成進度導向的「還差 1 步」而不是失敗導向的「服務未啟用」——同樣的狀態，但告訴使用者離完成有多近。
  • 已完成的那一步用綠勾收起來，待辦那步直接掛上「前往設定」。使用者不用自己在卡片和底下的按鈕之間對應。
  • 這一頁不顯示任何設定。現況已經是這樣（isListenerEnabled 為 false 時不 render SettingsCard），改版維持相同邏輯，只是補上「先了解一下」讓等待中的使用者有事可做。

聊天室：讓狀態說話，而不是讓開關自己解釋

  • 副標從「好友／群組」換成實際狀態。chat_status_enabled／chat_status_disabled／chat_legacy_original_only 這三個字串本來就存在，但目前列上顯示的是分類——而分類已經由上面的 chip 和分區標題表達過了，重複佔位。
  • 「舊設定」用琥珀色標出來。這是 v1.3.0 最容易讓人困惑的狀態（關了卻還會跳 LINE 原通知），現在能一眼掃出哪幾間需要重開再關。
  • 依分類分區並顯示數量，取代一條到底的長清單。142 間聊天室時，這是唯一能維持可讀性的做法。
  • 右上角改成選取模式的入口。批次選取（chat_select_all、chat_bulk_enable）已經實作了，但目前沒有明顯的進入點。
  • 搜尋常駐而不是藏在放大鏡後面——有幾百間聊天室時，搜尋是主要導覽方式，不是次要動作。

設計 Token

綠色留著，但要分成四階

單一個 #06C755 撐不起整個介面——它太亮，白字放上去只有 2.26:1 對比，遠低於 WCAG AA 的 4.5:1。 解法不是換掉綠色，而是把它拆成「裝飾用」與「承載文字用」兩種深淺。 你的 Color.kt 其實已經有 Green30 #059B43、LightGreen、DarkGreen，只是沒被用起來。

四階綠

#06C755 標誌與狀態點（裝飾，不放字）
#05A847 開關軌道、選取邊框（對白底 3.1:1 ✓）
#05873C 實心按鈕底（白字 4.6:1 ✓）
#04672C 綠色文字（白底 7.0:1 ✓）

關掉 dynamicColor

這是最關鍵的一行。目前 dynamicColor = true，Android 12 以上會用桌布取色覆蓋掉你的綠色——大多數使用者看到的根本不是 LINE 綠。關掉之後綠色才真的會出現，Play 截圖也才會跟實機一致。

表面：白卡浮在淺灰底

現況是灰卡浮在白底，導致卡片看起來比背景「低」。反過來之後，主控制卡加一層極淺陰影就能自然浮起，不必靠顏色搶注意力。

四級字階

現況大多落在預設 M3 字級，主開關和說明文字的對比不夠。四級就足夠拉開層級。

深色模式

深色底上的綠要提亮到 #3DDC84 一帶才夠對比，直接沿用 #06C755 會顯得髒。現況靠 dynamicDarkColorScheme，品牌同樣不受控。
